## 1. Methodology

Differential testing validates that independent clean-room implementations match or intentionally and provably improve upon established, trusted firmware tooling.

FriedChip+ incorporates automated differential assertions inside its unit/integration test suite:
- **Dell PFS Extraction**: Validated against reference outputs generated by Plato Mavropoulos's `BIOSUtilities` on an authentic OEM BIOS update package (`Latitude_5X90_1.41.0.exe`).
- **Intel Flash Descriptor Decoding**: Validated field-for-field against `coreboot` `ifdtool` reference values and bit shifts across legacy and modern descriptor profiles.

### 2.2 Documented Format Deltas (3 Components)

Three extracted components exhibit deliberate, fully documented behavioral differences between FriedChip+ and BIOSUtilities:

| Component | BIOSUtilities Behavior | FriedChip+ Behavior | Engineering Justification |
|---|---|---|---|
| `Firmware` | Recursively strips the outer `PFS.HDR.` envelope and outputs inner raw stream | Preserves the clean bounded raw container with metadata and headers intact | FriedChip+ maintains container provenance for forensic verification; inner nested extraction is performed in a clean sub-pipeline without destructive modification of container boundaries. |
| `EmbeddedController` | Strips proprietary 64-byte Dell EC header before emitting binary | Emits verified uncompressed payload preserving full bitwise fidelity | Eliminates silent header stripping, ensuring differential test repeatability and exact checksum verification. |
| `MainSystemBios` | Decapsulates Intel PFAT / Phoenix block metadata into loose segments | Extracts complete bounded raw stream and verifies XOR and CRC-32 | In accordance with the Phase 2 charter, PFAT decapsulation is deferred to Phase 3; FriedChip+ guarantees uncorrupted bit-level extraction of the raw container. |

### 2.3 Component Description Tables (CDT)

Both CDT metadata sections (`CDT_0` and `CDT_1`) were discovered, extracted, and verified identical in structure and offset.

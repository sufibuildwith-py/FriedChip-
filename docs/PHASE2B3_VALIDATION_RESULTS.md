## 1. Test Architecture & Reconciled Inventory (DEF-45)

The FriedChip+ test suite is organized into distinct validation tiers. To ensure absolute honesty in engineering reporting, tests are categorized by their execution requirements and external dependencies.

### 1.1 Test Tier Classification
1. **Tier 1 — Unit & Synthetic Structure Tests (Always Executed)**:
   - Self-contained deterministic unit tests using byte-level synthetic fixtures constructed by `SyntheticFixtureBuilder`.
   - Exercised on every `cargo test` run.
   - Requires zero external binaries or network access.
2. **Tier 2 — Bounded In-Process Structure-Aware Mutation / Stress Tests (Always Executed)**:
   - 300,000 iterations (100,000 IFD, 100,000 Dell PFS, 100,000 UEFI Firmware Volumes).
   - Monitored by test-only thread-local observer hooks with zero production overhead.
   - Asserts both positive (accepted) and negative (rejected) branches for signatures, geometry, checksums, ZLIB streams, and sentinels.
3. **Tier 3 — Stored Golden Differential Regression Tests (Always Executed)**:
   - Evaluates engine extraction outputs against pre-computed golden metadata and SHA-256 hashes generated by independent upstream references (`BIOSUtilities` and `coreboot ifdtool`).
   - Manifest: `fixtures/manifests/dell_latitude_5x90.json`.
   - Exercises real-world parser compatibility without requiring redistribution of proprietary OEM binaries.
4. **Tier 4 — Live OEM Fixture Integration Tests (Explicitly Ignored / Skipped when Fixture is Absent)**:
   - Live end-to-end extraction against proprietary OEM executables (e.g. `Latitude_5X90_1.41.0.exe`).
   - Located in `fixtures/realworld/`.
   - When the physical OEM fixture is not present on disk, tests return `#[ignore]` (SKIPPED).
   - **Crucial Rule**: Skipped tests are **NEVER** claimed as real-world validated. Corrupted or hash-mismatched fixtures trigger an immediate `panic!`.

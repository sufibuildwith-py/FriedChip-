## 2. DEF-31: Coreboot `ifdtool` Classification Remediation

In Phase 2B, the test suite included a test named `test_ifd_differential_regression_against_coreboot_ifdtool`. Independent review noted that running `ifdtool` as a live subprocess on Windows is blocked because `ifdtool.c` directly includes POSIX headers:
```c
#include <sys/mman.h>
#include <unistd.h>
```
Under Windows native MSVC/Rust toolchains, compiling or executing `ifdtool` directly without Cygwin/WSL is unavailable. Therefore, the test was executing against golden vectors extracted from upstream `ifdtool`.

In Phase 2B.1, this test was explicitly renamed and reclassified:
- **New Test Name:** `test_ifd_golden_vector_regression_against_coreboot_ifdtool`
- **Classification:** `GOLDEN_VECTOR_REGRESSION`
- **Reference Commit:** coreboot `66e704b1`
- **Vector Description:** 16MB IFD v1 image with 5 standard regions (Descriptor, BIOS, ME, GbE, Platform Data), standard master permissions, 50 MHz read clock.
- **Verification Result:** 100% agreement on all decoded offsets, limits, master access masks, and component densities.

### 3.2 Three (3) Documented Clean-Room Divergences

For 3 components, FriedChip+ intentionally diverges from BIOSUtilities. These divergences reflect deliberate clean-room engineering decisions:

#### 1. System BIOS with BIOS Guard (PFAT Encapsulation)
- **BIOSUtilities Output:** 8,847,360 bytes (SHA-256: `3B5CD7C...`). BIOSUtilities attempts an in-situ strip/decapsulation of Intel BIOS Guard (PFAT) structures.
- **FriedChip+ Output:** 9,001,316 bytes (SHA-256: `16260C135E0BC8A832C99DBBC809EB86599C72E809E9E73210EBD42057BA944D`).
- **Engineering Justification:** In Phase 2, PFAT decapsulation is explicitly **OUT OF SCOPE**. Stripping PFAT blocks without verifying signature authenticity or block offsets risks generating corrupt SPI flash images. FriedChip+ preserves the exact raw PFS section payload and flags it with classification:  
  `"Encapsulated OEM Firmware (Unverified SPI Layout - Requires Phase 3 PFAT Module)"`.

#### 2. PCR0 XML Metadata
- **BIOSUtilities Output:** 2,476 bytes (on Windows). Python opened the output file in text mode (`w`), automatically converting Unix LF (`\n`) newlines to Windows CRLF (`\r\n`), altering file size and checksum.
- **FriedChip+ Output:** 2,452 bytes (SHA-256: `BA5B0CB32C1A63CE67D4D154726B81308E8452ECEDDC9E7F638C7B9422AC4124`).
- **Engineering Justification:** Pristine binary fidelity. Firmware extraction tools must never silently mutate payload byte streams through OS newline translation.

#### 3. Model Information Block
- **BIOSUtilities Output:** 111 bytes. Python stripped the trailing null delimiter byte.
- **FriedChip+ Output:** 112 bytes (SHA-256: `353B1D39F415D3B6F93F8BA88B9CC078C8B0624EB93B9D15B8718AD55EC973A3`).
- **Engineering Justification:** Exact preservation of raw section data as emitted by Dell PFS container framing.

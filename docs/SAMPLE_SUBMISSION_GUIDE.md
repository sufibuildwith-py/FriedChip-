# Firmware Sample, Test Fixture & Evidence Submission Guide

To ensure clean-room compliance, privacy protection, and reproducible testing, follow these guidelines when submitting test packages, firmware dumps, and UI workflow evidence.

---

## 1. Testing Policy & Sample Priority

To ensure data protection and reproducible test fixtures, test materials are prioritized as follows:

1. **Synthetic Binary Fixtures (Top Priority):**
   - Deterministic byte buffers generated by our test suite (e.g. synthetic IFD with signature `5A A5 F0 0F`, corrupted headers, mock UEFI volumes, ambiguous EC slices).
   - Zero privacy or copyright concerns.
2. **Public Manufacturer Update Packages (Recommended for Extraction Tests):**
   - Non-confidential update packages downloaded directly from official OEM support websites.
   - **Candidate Reference Models:**
     - **Dell Latitude 5490** (PFS/HDR container)
     - **HP EliteBook 840 G5** (Insyde encrypted payload)
     - **Lenovo ThinkPad T480** (InnoSetup / FL1 / FL2 payload)
   - Store binaries locally in `firmware-samples/public-updates/` (git-ignored).
   - Document: Official URL, Package Version, Download Date, and SHA-256 hash.
3. **Bench Dumps & Paired Diagnostic Samples:**
   - Used for validating ME health checks, EC slicing, and DMI preservation.
   - **Privacy Policy:** Never submit customer-sensitive dumps containing corporate credentials, Wi-Fi keys, or personal identifying information. Ensure dumps originate from authorized lab test units.

## 4. UI Evidence Submission (For Phase 0 Workflow Mapping)

When submitting screenshots or screen recordings from LBE++:
- Document the exact module opened (e.g. *Dell Extractor*, *Smart ME*, *DMI Editor*).
- Record the input file format and size.
- Record the exact parameters chosen (e.g., ME version selected, EC size heuristic).
- Note all output files produced, their sizes, and any diagnostic console messages.
- Place images in `firmware-samples/evidence/screenshots/`.
